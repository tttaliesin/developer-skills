# README authoring

처음 방문한 독자의 판단과 첫 사용을 돕는 저장소 README 작성·편집·검토
인기 저장소의 외형을 복제하는 대신 실제 독자 과제와 저장소 근거로 내용 선택

## 잘 만든 README의 조작적 정의

의도한 독자가 README와 명시적으로 연결된 시작 문서를 이용해 다음 과제를 수행할 수 있는 진입 문서

- 무엇을 위한 프로젝트이며 자신의 목적에 맞는지 판단
- 제공되는 결과를 구체적인 예시나 자료로 파악
- 필요한 조건을 갖춰 첫 유효 작업을 수행하고 성공 여부 확인
- 다음 사용·학습·문제 해결에 필요한 문서 탐색

판정 근거는 문서 위치, 실제로 따라간 경로와 관찰 결과
스타 수, 배지 수, 글자 수와 작성자의 자기평가는 품질 판정 근거에서 제외
이는 관찰 사례를 바탕으로 설계한 운영 기준이며 사용자 실험으로 검증된 품질 척도는 아님

## 요청과 독자부터 확정

작성·전체 재구성·국소 수정·검토 중 요청한 작업과 대상 README 확인
저장소 지침, 현재 README, 배포·실행 설정, 대표 코드·예제와 기존 문서에서 주 독자와 첫 작업 추론
이미 확인할 수 있는 내용을 다시 질문하지 않고, 결과를 크게 바꾸는 정보만 확인
프로젝트 이용자와 소스 기여자의 시작 경로가 다르면 주 독자의 경로를 먼저 배치

전체 작성·재구성·평가에는 [작성·판정 기준](references/reader-outcomes.md)을 읽고 적용
국소 수정에는 직접 영향받는 항목만 적용하며 기존 문체·구조·앵커 보존
검토만 요청받으면 파일을 수정하지 않고 문제, 근거와 미확인 범위 보고

## 필요한 내용만 작성

소개 → 구체적인 결과 → 첫 작업 → 필요한 다음 문서의 흐름을 출발점으로 사용하되 고정 목차로 강제하지 않는 방식
자료 모음은 분류와 자료 선택이 첫 작업이고, 도구는 실행과 결과 확인이 첫 작업
라이선스·출처·운영 설명은 이용 조건이나 독자의 선택에 영향을 줄 때 포함하고 확인된 사실만 기재
이미 들어와 있는 저장소 주소, 내부 작업 분담, 배포 관리 설명을 독자에게 쓸모없는 자기 설명으로 추가하지 않는 원칙

`markdown-authoring`이 제공되면 문법·렌더러·링크 검증에 함께 적용
없어도 이 스킬의 독자 과제 검증을 계속하고, 기본 Markdown 구조·복사 가능한 명령·상대 링크·이미지 대체 설명을 직접 확인
원본의 문구, 로고, 배지, 상업적 홍보와 특정 에이전트 운영 방식을 관행으로 복제하지 않는 원칙
사례의 선정 방법이나 기준의 근거를 설명·수정할 때만 [조사 근거](references/research.md) 추가 확인
일상적인 README 작성마다 Trendshift 재조사 불필요

## 첫 작업을 따라가며 검증

명령·경로·옵션·지원 범위는 현재 코드·설정·공식 문서와 대조
실행 가능한 경우 기존 검증 환경에서 부작용 없는 실행이나 격리된 예제로 README의 안내를 그대로 따라가고 관찰 결과 확인
자료 모음에서는 대표 분류에서 실제 자료까지 이동하고 자료 내용이 링크 설명과 일치하는지 확인
실행하지 않은 명령은 코드·설정·도움말·테스트·공식 문서와 대조했더라도 `정적(static)` 확인으로 기록하고 실제 실행 성공과 구분
접근하지 못한 링크와 알 수 없는 제품 동작은 미확인으로 보존하고 출력·설치 성공을 생성하지 않는 원칙
README 검증을 이유로 제품 구현, 전역 환경이나 운영 서비스를 변경하지 않고 실제 실행 권한과 부작용 범위 유지

최종 응답에는 변경된 README, 주요 개선점, 실제 수행한 확인과 남은 한계 제시
상세 평가표와 작업 메모를 작성 대상 README에 자동 삽입하지 않고, 사용자가 평가를 요청하면 별도 검토 결과로 제공
