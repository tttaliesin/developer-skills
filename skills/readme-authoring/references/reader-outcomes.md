# 작성·판정 기준

목차의 존재 여부보다 독자가 실제로 답을 찾고 행동할 수 있는지를 판정하는 기준
관찰 근거는 [조사 기록](research.md)에 연결하고, 아래 판정 방식은 그 관찰에서 도출한 설계로 구분

## 평가 단위와 상태

주 독자, 해당 독자의 첫 유효 작업, 검토한 README revision과 환경을 작업 메모에 짧게 기록
예: 로컬 파일을 변환하려는 Python 사용자 / 예제 파일 하나를 Markdown으로 변환 / 현재 checkout
기본적인 언어·도구 지식은 대상 독자에 맞게 가정하되 저장소 내부 구조나 미기재 설정을 이미 안다고 가정하지 않는 원칙

각 항목을 다음 상태와 문서 위치·관찰 근거로 기록

| 상태 | 판정 조건 |
| --- | --- |
| 충족 | 명시된 독자 과제를 문서와 검증 근거로 수행할 수 있고 중요한 추측이 필요 없는 상태 |
| 미충족 | 필요한 안내가 빠졌거나 모순·실패·불필요한 우회가 확인된 상태 |
| 미확인 | 안내는 있으나 실행·접근·권한 또는 근거 부족으로 정확한 작동 여부를 확인하지 못한 상태 |
| 해당 없음 | 그 세부 검사가 독자 과제에 적용되지 않는 이유를 제시할 수 있는 상태 |

검증 방법은 실제로 안전하게 수행한 `실행(executed)`, 코드·설정·도움말·테스트·공식 문서와 대조했지만 끝까지 수행하지 않은 `정적(static)`, 근거가 부족한 `미검증(not verified)`으로 기록
설치 대상이 없는 목록에서는 설치 검사만 해당 없음으로 처리하고 첫 사용 축 자체는 자료 탐색으로 평가
정상 명령의 실행 환경이 없으면 미확인으로 처리하며, README에 필수 명령 자체가 없으면 미충족으로 처리

전체 작성·개편은 아래 여섯 축을 평가하고 국소 수정은 직접 영향받는 축만 평가
전체 품질 충족 판정은 적용되는 검사가 모두 충족일 때만 사용
미충족은 수정할 문제와 영향을, 미확인은 판정에 필요한 증거와 제약을 구분해 보고
부분 검토나 `정적(static)` 대조만으로 실제 실행 또는 모든 독자의 이해를 검증했다고 표현하지 않는 원칙
명령 오류·잘못된 제품 설명·끊긴 시작 경로는 다른 장점이나 합산 점수로 상쇄하지 않는 방식
보편적인 시간 제한, 단어 수와 합격 점수를 설정할 실험 근거는 없으며 필요한 경우 프로젝트별 목표로 별도 합의

## 여섯 가지 독자 과제

### 목적과 적합성

상단 소개와 시작 안내에서 프로젝트의 용도, 주 독자가 얻는 결과와 선택에 중요한 조건을 파악할 수 있는지 확인
광고·연혁·내부 구조를 먼저 읽어야 목적이 드러나거나, 추상적인 수식어만으로 제품을 설명하면 미충족
적합성에 중요한 제약만 가까이 배치하고 모든 프로젝트에 별도 비대상·주의사항 절을 강제하지 않는 방식

관찰 과제: 저장소를 처음 보는 독자의 입장에서 무엇을 어떤 용도로 사용할지 설명하고 그 근거 문장 지목
대상 독자에게 중요한 입력·플랫폼·이용 조건이 있다면 같은 경로에서 찾을 수 있는지 추가 확인

### 구체적인 결과

대표 입력과 출력, 실제 화면, API 사용 예제, 학습 과제 또는 자료 항목으로 제공 가치를 확인할 수 있는지 평가
기능 이름만 나열하고 실제로 무엇을 얻는지 판단할 수 없으면 미충족
카탈로그의 실제 항목이나 강좌의 과제도 충분한 증거이며 별도의 데모·스크린샷 절을 추가할 필요 없음

관찰 과제: 대표 사례 하나를 고르고 사용자가 얻는 결과 지목
출력 예시는 실제 실행·기존 예제·확인된 동작을 근거로 작성하고 정확 출력과 설명용 요약 구분
근거 없는 성능 수치, 도입 기업, 사용 후기나 성공 결과 생성 금지

### 첫 사용의 완결성

필수 조건 → 시작 행동 → 입력·설정 → 결과 확인이 하나의 따라갈 수 있는 경로인지 평가
필요한 실행 위치, 도구·버전, 권한·계정과 비밀이 아닌 예제 입력을 해당 단계 전에 제시
대안을 제공할 때 선택 기준을 붙이고 어느 경로부터 시작할지 드러내는 방식

관찰 과제: 안내 순서대로 첫 작업을 수행하면서 문서 밖에서 추측한 필수 단계를 기록
누락된 필수 단계, 실행 불가능한 예제나 성공 확인의 부재가 있으면 미충족
설치만 끝났다는 사실과 제품의 첫 유효 작업 완료를 구분

설정이 큰 제품은 기존 Quickstart로 연결 가능
이 경우 README에 정확한 진입 링크·시작 조건·얻을 결과를 남기고 연결된 시작 절차까지 함께 검토
링크 하나만 있다는 이유로 모든 절차가 검증됐다고 판단하지 않는 원칙

### 탐색과 상세 문서 분리

독자가 다음 사용·학습·문제 해결 경로를 제목과 설명 있는 링크에서 선택할 수 있는지 평가
공통 시작 경로는 눈에 보이게 두고 상세 옵션·개발 환경·기여 절차는 필요할 때 따라갈 수 있도록 배치
문서 자체가 학습 자료나 카탈로그인 경우 긴 본문도 유효하며 길이만으로 분리하지 않는 방식

관찰 과제: 첫 사용 뒤 필요한 질문 하나를 선택하고 해당 절이나 문서까지 이동
짧은 문서에는 수동 목차를 강제하지 않고 긴 자료는 분류·검색·목차 중 실제 탐색을 돕는 수단 선택
잘못된 링크, 이름만 다른 중복 진입점과 시작 전 불필요한 문서 왕복은 미충족 근거
이미지와 접힌 영역만으로 필수 조건이나 행동을 전달하지 않는 원칙

### 사실과 실행 안내의 정확성

제품 동작, 경로·옵션, 버전·설치 방법, 지원 환경과 중요한 이용 조건을 현재 저장소 또는 공식 근거와 대조
배지나 다른 프로젝트의 관행을 사실 근거로 사용하지 않는 원칙
라이선스·지원 채널·공식 배포 주소는 존재와 의미를 확인하며 없다고 임의로 신설하거나 추정하지 않는 방식

관찰 과제: 첫 사용 경로의 명령·링크·설정과 주요 제품 주장을 각각 원천에 연결
안전하게 실행할 수 있으면 안내 그대로 확인하고, 정적 대조만 수행했으면 그 범위를 명시
외부 링크의 응답 성공만으로 연결된 내용이나 서비스 기능까지 맞다고 판정하지 않는 원칙
실패가 문서 결함인지 환경·권한·외부 서비스 문제인지 구분하고 미확인 원인을 구체적으로 기록

### 정보 선별

각 절·문단·배지가 독자의 선택, 실행, 탐색 또는 중요한 이용 조건 이해에 기여하는지 평가
역할을 설명할 수 없는 반복·홍보·자기 설명은 삭제하거나 적절한 기존 문서로 이동
예: 독자가 이미 읽는 저장소를 다시 배포 원본으로 소개하는 문장은 일반적으로 제거 대상
다만 공식 배포처 구분, fork의 호환성이나 라이선스 출처처럼 선택에 영향을 주면 유지

관찰 과제: 문단을 제거했을 때 잃는 독자 정보가 무엇인지 확인
아무 정보도 잃지 않거나 다른 문단과 동일하면 중복으로 판정
첫 성공에 필요한 제약·예제까지 삭제해서 짧아진 문서는 이 기준을 충족하지 않는 상태
연구 경위·내부 담당자·작업 기록은 사용자가 그 독자를 지정하지 않는 한 README 본문의 기본 항목에서 제외

## 프로젝트별 첫 작업 해석

다음은 내용 선택을 돕는 예시이며 강제 목차가 아님

| 프로젝트 | 첫 유효 작업 | 성공 확인의 예 |
| --- | --- | --- |
| CLI·라이브러리 | 대표 명령 실행 또는 최소 API 호출 | 관찰된 출력·생성 파일·반환값 |
| 앱·서비스 | 접근·설정 후 대표 기능 이용 | 실제 화면 상태·응답과 기능 결과 |
| 자료 모음 | 목적·언어·주제에 맞는 항목 선택 | 설명과 일치하는 자료에 도달 |
| 강좌·학습 계획 | 수준·선행 지식에 맞는 시작 과제 선택 | 첫 학습 단위와 수행할 과제 확인 |
| 스킬 모음 | 필요한 스킬 선택·설치 후 해당 요청에 사용 | 스킬 발견과 요청에 맞는 동작 확인 |

앱 실행이나 에이전트 동작이 비용·인증·외부 효과를 요구하면 그 경계를 확인하고 검증 범위 제한
README 작성 요청을 운영 변경이나 무제한 실험의 승인으로 확대하지 않는 원칙

## 결과 전달

전체 평가를 요청받았을 때만 다음 형태의 근거표를 별도 검토 결과로 사용

| 기준 | 판정 | 위치와 확인 방법 | 남은 문제 |
| --- | --- | --- | --- |
| 첫 사용의 완결성 | 미확인 | 시작 절의 명령을 CLI 정의와 정적 대조 | 대상 서비스에 접속하지 않아 응답 미확인 |

작성·수정 요청에는 실제 파일과 중요한 개선·검증·한계만 전달
발견한 문제를 고치라는 요청이 없는 검토에서는 판정과 근거 제시로 완료
